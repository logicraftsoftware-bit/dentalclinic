# Acceptance evidence and release limits

The MongoDB/Vercel conversion preserves the existing clinic and platform workflows while replacing PostgreSQL dependencies. Current verification uses an isolated local MongoDB 8.0 replica set with synthetic data, not the user's Atlas cluster. The previous PostgreSQL release and restore evidence apply only to the historical commit, not this MongoDB release.

Implemented conversion: MongoDB-compatible Prisma models with UUID string IDs; tenant-scoped repository reference checks; transaction conflict/retry locks; non-null unique provider/session-source identities; shared atomic rate counters with TTL cleanup; an import-safe Vercel API entry point and same-origin routing; bounded authenticated cron; private S3 document storage; updated setup scripts and CI.

Verified in this conversion: eight unit tests and twenty-two MongoDB integration checks, covering registration and verification, scoped reads/writes/related IDs, concurrent plan limits, charts/clinical notes, treatment session invoices, installment replay/commissions, cross-clinic document denial, suspension/subscription entitlement checks, consented support, webhook/refund replay, reconciliation with synthetic provider responses, shared rate counters, cron leases and refusal of ephemeral storage on Vercel. Verified on 15 October 2026: all three browser workflows passed, including delayed chart loading; the production TypeScript/Vite/API build passed; the Vercel handler and compiled API imported without starting a listener; the production dependency audit reported zero vulnerabilities. Total: 33 automated checks.

Still requires operator configuration and external verification: Atlas URI/network access, target-database schema/index setup, one-time administrator seed, APP_URL/BASE_DOMAIN, SMTP, private S3 permissions, Razorpay live/sandbox credentials, Vercel cloud deployment and provider delivery. No real Atlas, Vercel, S3 or SMTP connection was exercised by these local checks.

This revision does not transfer existing PostgreSQL records. Preserve their backups and rehearse any import separately. MongoDB/object-store backup and restore correctness has not yet been rehearsed. Select managed backups/versioning, verify recovery counts and finance totals, and monitor orphan objects before production.

Remaining commercial work includes automated recurring mandates, configurable branch permissions, optional MFA, malware scanning, legally reviewed privacy/retention policies, immutable external audit logs, independent security/load tests, monitoring, durable delivery queues and disaster-recovery drills. A daily cron page of ten clinics is suitable for initial testing; larger installations need more frequent processing. SMTP delivery interrupted after provider acceptance remains uncertain and needs review rather than blind resend. This is not a healthcare compliance certification or completed commercial launch.

Email verification is disabled at the user's request. Clinic registration and staff creation do not send verification codes or require SMTP; both new and existing accounts can authenticate immediately using their passwords and active memberships. Email ownership is not asserted by this flow. Password-reset emails and subscription reminders still require SMTP. Verified locally: 9 unit tests, 24 integration tests and 3 browser workflows (36 total), plus the production build. The live health endpoint returned status ok before publishing this change.

Clinic masters release: Speciality, Charge group and Charge masters support add/edit/search/activate/deactivate; owner/manager mutation permissions; scoped clinical/reception reads; related-master checks; duplicate/amount validation; doctor speciality selection; charge-driven treatment defaults; historical price/lab snapshots; and full-clinic export. All 39 checks passed (9 unit, 27 integration, 3 browser) plus the production build. The browser workflow creates all three masters, assigns a doctor speciality and selects a treatment charge. Integration checks also exercise first use with the new collections absent, proving no database reset is needed.
