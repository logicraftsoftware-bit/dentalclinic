# Architecture

React/TypeScript -> same-origin Express API -> Prisma 6.19 -> MongoDB replica set. Vercel serves the Vite frontend and api/index.ts function. Private S3 storage persists documents; local filesystem storage is permitted only outside Vercel.

Authentication uses opaque hashed revocable sessions, HttpOnly cookies, mutation-origin checks, password authentication and active membership checks. Platform administrators use separate authorized endpoints. Clinic APIs require an actual membership even for a platform administrator. Hostnames provide an additional membership boundary; they are not authentication credentials.

Every clinical record has tenantId. TenantStore injects that tenant into reads/counts and compound selectors for updates/deletes, strips identity fields on updates, rejects nested mutation inputs, and checks each supplied clinical foreign reference within the same tenant. MongoDB does not provide PostgreSQL row-level security or composite foreign keys. Raw database access is therefore privileged: only the central clinic authorization layer, explicitly authorized platform routes, seed and workers may use it. Do not expose raw Prisma to new clinic routes. UUID strings map to MongoDB _id and preserve API validation.

Each clinic transaction writes a shared TransactionLock document before checking membership/status and performing operations. MongoDB aborts conflicting transactions; bounded exponential retries rerun the transaction against a fresh snapshot. This protects count-based plan limits, appointment conflicts and payment allocations across function instances. Registration and webhook processing also write scoped lock documents. Unique event/payment/idempotency indexes prevent duplicate effects. Clinic and platform transaction replies are buffered until commit. Provider calls should stay outside retryable transactions.

Rate limiting uses atomic MongoDB counters shared by all function instances. Keys hash IP addresses and fixed time windows. A TTL index removes expired counters. Cron uses a persisted lease and clinic cursor, with bounded processing; it does not disconnect the shared client or execute automatically on module import.

Money uses integer minor units. Patient invoices/payments/commissions and platform subscription invoices/payments remain separate collections and routes. Webhook processing verifies HMAC, server-owned order, amount, currency and capture status. Missing provider IDs get unique UUID placeholders to avoid MongoDB unique-index null collisions; reconciliation selects only order_ provider IDs. Optional session IDs are indexed; a non-null compound-unique sourceKey uses the session ID for session invoices and a UUID for manual invoices, preventing MongoDB null collisions while retaining session-invoice uniqueness.

MongoDB transactions require a replica set (Atlas provides one). Schema/index synchronization uses db:push; changing existing data requires versioned conversion scripts and restore-tested backups, not SQL migrations. This revision initializes new MongoDB databases; it does not transfer historical PostgreSQL records.

Clinic masters use tenant-owned Speciality and ChargeGroup collections. The charge master reuses CatalogItem with optional chargeGroupId and labChargePaise (default zero), preserving previous catalog IDs/prices/sessions. Doctors can hold a specialityId while retaining their previous specialty text. TreatmentItem stores an optional catalogItemId plus a lab-price snapshot. Related masters are checked through TenantStore; names are normalized and duplicate-checked under the clinic transaction lock. Retired entries are retained and linked active records prevent unsafe deactivation. Master records appear in full-clinic exports, never unrelated patient-only exports. New collections can initialize on first use without resetting existing data; db:push adds the declared compound indexes during normal schema maintenance.
